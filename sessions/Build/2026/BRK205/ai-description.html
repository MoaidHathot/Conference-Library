Aspire is a code-first tool for distributed apps It helps developers compose, debug, and deploy distributed applications from a single structured setup. Distributed apps include common app patterns Even a simple website connected to a database is considered a distributed app, so Aspire applies to many real-world projects. Aspire improves the local development experience It connects all app components so developers can run and debug systems locally in a way that feels closer to production. The app host acts as the central control file One app host defines resources, dependencies, environment settings, startup order, and deployment behavior. Aspire supports reusable integrations It includes integrations for services like PostgreSQL, Redis, Azure Container Apps, and more, while still allowing customization. The Aspire dashboard provides observability Developers can inspect resources, logs, traces, metrics, environment values, and app relationships from a single place. OpenTelemetry is a core part of the experience Aspire uses OpenTelemetry to surface structured logs, distributed traces, and metrics across frontend, backend, and supporting services. Aspire is designed to work well with coding agents It gives agents a deterministic way to understand app structure, ports, dependencies, logs, and health without scanning everything manually. It simplifies setup and environment management Aspire manages ports, certificates, environment variables, secrets, and resource provisioning so developers avoid repetitive manual configuration. Aspire bridges development and deployment The same app host used for local development can also generate deployment assets and target environments like Azure Container Apps, making it useful across the full lifecycle.
