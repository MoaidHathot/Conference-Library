Introduction to Microsoft Foundry: At the start of the session 00:00:00–00:00:30, Tina Schackman and Jeff Holland introduce themselves and outline the purpose of the presentation—showing how to build, deploy, and operate local AI agents using the Microsoft Foundry platform. Tina sets the stage by detailing the evolution of AI agents: building is now easy, agents can learn and create new skills spontaneously, and they function as teammates rather than simple tools. She emphasizes that successful enterprises operate coordinated agentic systems across business domains such as compliance, finance, and supply chain, powered by Microsoft’s integrated ecosystem—Foundry, Azure, GitHub, and Microsoft 365 00:02:57.

Demo Scenario and Developer Build Phase: Moving into the demo 00:04:39–00:07:00, the presenters use a real-world incident at an Azure datacenter—a fiber cable cut near a facility—to illustrate how Foundry supports autonomous response agents. The “Fiber Outage Response Agent” detects the outage, gathers reliability data in Fabric IQ, supplier details in Work IQ, and contractual documents through content understanding, then dispatches field reps, logs activity in D365, and updates stakeholders in Teams. Jeff transitions into building that agent, explaining how developers use Foundry’s developer toolkit within Visual Studio Code 00:08:16. He covers framework and model selection, context integration, and security while highlighting the Foundry Toolkit extension, which consolidates all essential components—tracing, evaluations, and model setup—directly in the editor.

Creating and Enhancing the Agent: Jeff demonstrates how to construct the agent with Microsoft’s Agent Framework 00:10:00–00:16:10, leveraging its harness for secure and dynamic execution of shell commands and code. Foundry Toolbox connects services like Fabric IQ, Foundry IQ, Teams, and Outlook, all through a unified authentication layer. With Tool Search enabled, the agent retrieves only contextually relevant data, optimizing memory and focus. Jeff enriches the agent further by adding a Content Understanding module that transforms PDFs into structured AI-readable content. He runs the agent locally, debugs via F5 in VS Code, and converses with it interactively. Finally, he voice-enables it in Foundry 00:16:20 by wrapping speech models automatically, allowing natural spoken interaction that retrieves fiber termination specifications in real time.

Deployment and Proactive Operations: Tina and Jeff move on to deploying at scale 00:20:00–00:28:00. Tina announces availability updates: Agent Framework v1.0 production release, Foundry Toolkit GA, Toolboxes and Skills integration, Voice live service, and upcoming general availability of hosted agents with sub‑second cold starts and secure isolation. Jeff then demonstrates “Hosted Agents” running continuously using Foundry Routines, making agents proactive by waking on timed events and performing anomaly investigations autonomously. He explains secure isolation of sessions and integration with Durable Task Scheduler—idle sessions cost nothing and resume instantly with full persistent state. The same agent, named “Phi B,” is published to Teams as a live Copilot companion, capable of responding in natural conversation while maintaining compliance with organizational identity and permissions.

Operating and Optimizing Agents: In the final section 00:29:00–00:38:00, Jeff dives into the Operate phase focusing on tracing, evaluation, and automatic optimization in Foundry. Using Trace Replay View, developers can inspect request timelines, tool calls, and token consumption visually. He demonstrates creating custom evaluation Rubrics with the Azure Developer CLI to prioritize criteria such as voice conciseness or tool selection accuracy 00:33:00. With Agent Optimize, Foundry loops through variations of prompts, model versions, and configurations automatically—returning ranked, higher‑performing agent candidates. Each outcome displays measurable improvements in quality, latency, and cost, ready for deployment as the newly optimized agent without manual retraining. Tina summarizes new operating capabilities—tracing pipelines, Rubric‑based evaluation, Agent Optimizer, and Procedural Memory—all enabling agents to learn persistently across sessions and self‑improve under developer governance.
