The talk is about engineering productivity in the AI era, focusing on how AI changes the way software teams work rather than just the products they build. Simple productivity questions like “Are developers 10x more productive?” are misleading, because metrics such as lines of code or PR counts do not reflect real business value. Developer time is divided across innovation, maintenance, and organizational work, with only a small portion of time spent actually coding. Active coding often takes only about 10–15% of an engineer’s week, showing that productivity cannot be measured by coding output alone. The real goal of productivity is to create more value faster, not just to increase visible activity or output. AI is reshaping the software development lifecycle, reducing the time spent on code creation and increasing the importance of planning and validation. Code is increasingly becoming an output of the system rather than the main input, while humans continue to provide architecture, verification, operations, and judgment. Microsoft’s EngThrive framework defines productivity as making it fast and easy to do great work, centered on three dimensions: speed, ease, and quality. The framework emphasizes outcome metrics over activity metrics, such as idea-to-customer time, innovation time ratio, and product quality instead of token usage or PR volume. Productivity should be measured at the system level, not the individual level, because the goal is to improve the engineering environment and remove bottlenecks rather than assess personal performance.
