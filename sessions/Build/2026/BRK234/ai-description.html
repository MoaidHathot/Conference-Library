The session focuses on how to scale custom AI models from fine-tuning to inference in real production environments, especially when GPU cost and performance optimization matter. The speakers stress that the biggest challenge is infrastructure, not just model recipes. Research may explain RL and fine-tuning well, but running them efficiently at scale requires deep systems-level optimization. Open models have advanced rapidly after DeepSeek R1, making frontier-style reasoning and RL post-training more accessible outside closed model APIs. Reinforcement learning is harder to operationalize than supervised fine-tuning because it combines inference and training in a repeated loop, which can significantly increase memory usage. Memory-saving strategies are essential for RL workloads. Techniques mentioned include offloading inference weights to RAM, memory weight sharing, standby/sleep modes, and gradient checkpointing. Gradient checkpointing is highlighted as a critical optimization because it reduces memory use by recomputing activations during backpropagation instead of storing everything. LoRA makes fine-tuning far more practical by updating only a very small percentage of parameters, dramatically lowering memory and compute requirements while still producing strong results. Reward design is described as one of the hardest parts of reinforcement learning. The challenge is not only maximizing reward, but defining the right reward function across different tasks and avoiding reward hacking. AI systems can cheat optimization goals if evaluation is weak. The discussion gives examples where models exploit benchmarks or loopholes, showing why robust verification and auditing are necessary. For builders, the highest leverage area is understanding system bottlenecks and optimization trade-offs. The speakers recommend focusing on math efficiency, compiler settings, memory behavior, kernels, and end-to-end infrastructure rather than only high-level model usage.
