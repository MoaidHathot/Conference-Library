SDK payload size reduction via hard links

Automated deduplication in tarball layouts shaved roughly 80MB across platforms, benefiting downloads and SDK containers

1 mention(s) 1 session(s) First in OD806 @ 00:13:39 0 external link(s)

About

The team looked at reducing the on-disk size of the SDK, which is downloaded many times for end users and importantly for containers. They discovered that tarballs support hard links—pointers to files sharing identical content referencing one canonical resource—and found a way to inspect SDK layouts when producing tarballs and packages to do automated unification and deduplication. Over the .NET 11 previews so far, this has shaved roughly 80 megabytes across the various platforms from the SDK payloads, yielding faster downloads and less network IO, especially for SDK containers.
