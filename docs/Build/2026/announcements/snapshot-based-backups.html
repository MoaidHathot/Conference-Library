Snapshot-based backups

Because page servers write to Azure storage, backups use storage snapshots without consuming compute to read pages, unlike traditional BACKUP DATABASE operations.

About

In Hyperscale, page servers continuously write back into Azure storage as a durable tier, which allows backups to use Azure storage's snapshot technology. Because of this, the compute layer is not involved in taking backups—no pages need to be read to perform a backup. This contrasts with traditional SQL, where BACKUP DATABASE reads all the data into compute and writes it back to the .bak file; that work is no longer needed with Hyperscale snapshot backups.
