Feature

Hyperscale named replicas with isolated working sets

Each named replica gets its own connection string, buffer pool, and RBPEX (Resilient Buffer Pool Extension) L2 cache, isolating read workloads from primary writes over the same up-to-128 TB dataset.

About

A major advantage of Azure SQL Hyperscale is named replicas, where each readable copy gets its own connection string. Each named replica has its own buffer pool (memory) and L2 cache—called RBPEX, the Resilient Buffer Pool Extension—giving it its own working set that is distinct from any other named replica, while all share the same underlying dataset of up to 128 TB. This isolation lets writes on the primary remain unaffected by reads, so customers can run continuous writes on the primary while pointing agents at a named replica for vector distance and cosine similarity work.
