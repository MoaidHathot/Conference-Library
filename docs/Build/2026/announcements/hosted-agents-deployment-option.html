Hosted agents deployment option

About

After finding that traditional compute with Container Apps—designed for stateless web services—wasn't built for the long-lived, stateful, per-user sessions that agents require, TAC switched to a hosted agents deployment option. Microsoft invested in hosted agents as a new compute primitive, recently going into public preview with WebSocket support and the Invocations API, which let TAC adopt it. The fully serverless option gives every session its own dedicated sandbox, predictable cold starts, scale-to-zero with no idle cost, state persistence, unique agent identity, and out-of-the-box observability, evaluations, and policies. In the new architecture, Twilio voice, SMS, and chat events flow over HTTP into an API Management Gateway that validates the Twilio signature, adds auth, and maps each Twilio conversation ID to a hosted agent session ID before routing into the sandbox, which connects to Azure Foundry for model inference.
