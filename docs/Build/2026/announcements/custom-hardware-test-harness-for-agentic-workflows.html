Custom hardware test harness for agentic workflows

A scripted orchestration layer (not unit tests, mocking, or manual QA) that connects to real hardware, deploys apps, and prints line-by-line output so a coding agent can see what worked and what failed

1 mention(s) 1 session(s) First in DEM365 @ 00:07:01 0 external link(s)

About

The speaker built a custom test harness after finding that coding agents like Copilot would confidently generate incorrect hardware implementations (e.g. for Bluetooth and NFC) that failed on real devices. It is not a unit test framework, mocking layer, or CI system, but a scripted orchestration layer that physically connects to real hardware, composes the allowed inputs for a test, and drives the system under test by deploying and running. Crucially it prints output line by line so the coding agent can see exactly which steps were taken and what worked or failed, since the hardware itself may have failed. It runs on the dev box, can deploy apps to a phone and cross-communicate with them, and supports USB connection and ADB on Android.
