Global secondary indexes (generally available)

Auto-syncing secondary containers partitioned for different access patterns, converting cross-partition queries into single-partition lookups

1 mention(s) 1 session(s) First in OD820 @ 00:42:11 2 external link(s)

About

Global secondary indexes are now generally available. They let you create a secondary container partitioned for different access patterns (for example, partitioned on destination) that automatically syncs data from a source container into a copy better suited for your query patterns. This transforms heavy cross-partition queries—like counting all trips to Paris across tenants—into single-partition lookups, increases query efficiency, and isolates heavy workload operations so they don't impact the transactional workload. When defining a GSI you can project only the most important properties, filtering out fields like the days array to match how you query the data.
