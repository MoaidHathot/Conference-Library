Azure DevOps remote MCP server

Two MCP servers (local and remote) now expose work items, repos, wiki, test plans, and pipelines; the remote server supports service principals, managed identities, and Microsoft Foundry agent creation, with Copilot Studio integration in progress

1 mention(s) 1 session(s) First in BRK202 @ 00:17:48 3 external link(s)

About

Azure DevOps now offers two MCP servers—a local and a remote one—both exposing the same tools for work items, repos, wiki, and test plans. The local server gives a top-tier experience when driven from VS Code with GitHub Copilot, while the remote server has consolidated tools and adds support for service principals, managed identities, and creating an agent in Foundry (it is part of that catalog). Copilot Studio integration has been in progress for several months and is hoped to arrive in the coming weeks. Two servers are kept because the remote server is built on Entra [inferred], whose restrictions currently prevent other clients like Claude, Cursor, or Codex from working with it.
