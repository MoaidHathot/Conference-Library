Guest VM-to-VM RDMA over Azure Boost

Demonstrated nearly doubling inference token throughput (3,400 to 7,637) and cutting median time-to-first-token from ~123k to ~47k ms in a disaggregated prefill/decode setup

1 mention(s) 1 session(s) First in BRK226 @ 00:11:00 2 external link(s)

About

This brings RDMA to general-purpose workloads by enabling memory-to-memory transfers between virtual machines through Azure Boost, bypassing the TCP/IP and MANA (Microsoft Accelerated Network Adapter) driver stacks to eliminate memory copies and synchronization overhead. The demo targeted a common AI inference scenario that splits work into prefill (populating the KV cache from the prompt) and decode (generating new tokens), running each in separate server pools with different memory and compute constraints. Using a VLLM benchmark over TCP/IP first, the RDMA send-request stats stayed unchanged while throughput was measured, demonstrating the contrast with the RDMA path.
