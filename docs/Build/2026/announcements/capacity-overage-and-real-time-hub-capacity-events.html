Capacity overage and Real-Time Hub capacity events

A 24-hour rolling CU limit for spikes and real-time alerts/triggers (e.g. Teams message when interactive delay hits 90%)

1 mention(s) 1 session(s) First in OD816 @ 00:09:43 2 external link(s)

About

Capacity overage acts as a safety valve, letting admins set a 24-hour rolling CU limit so workloads can spike above capacity during crunch time without throttling. Paired with this, the Real-Time Hub exposes capacity overview events where admins can set alerts—for example, filtering on when the interactive delay threshold hits 90% and firing a Teams message. Together these give real-time visibility and the ability to set up triggers and actions before problems surface, complemented by capacity metrics and chargeback apps for root-cause analysis.
