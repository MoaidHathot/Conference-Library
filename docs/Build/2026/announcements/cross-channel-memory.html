Cross-channel memory

When enabled per session, the agent extracts facts and carries context across web, phone, and text so users do not re-explain.

About

In a live demo using an airline use case, the presenter calls the agent and Twilio handles speech in and out while TAC bridges into the Foundry agent framework for reasoning. On the voice call, the agent identifies the caller's flight 543 to Seattle and changes their seat from 23B (an aisle seat) to 23A (a window seat). The presenter then switches to SMS and texts to add a bag to the reservation, and the agent responds remembering the prior voice conversation—correctly noting the customer is on flight 543 in seat 23A, the seat just changed two seconds earlier. This demonstrates shared customer memory across channels, resolved via profile resolution on the phone number.

  • ODSP92600:08:19
    Build collaborative agents into apps with APIs
    Ziv Navoth, Edo Segal, Gillian Sheldon

    Memory can be turned on at the channel layer: when you start a session for a user, you tell the Omniagent API to remember, and from that point the agent extracts facts, summarizes conversations, and carries that context forward automatically. Memory follows the user across every channel, so a conversation can start in a web app, continue on the phone, and be picked up over text the next morning. The result is the same agent with the same context and no re-explaining.
