Copilot `--cloud` on GitHub sandboxes

Stateful, isolated fast micro-VMs with tightly scoped credentials, letting users delegate tasks to run in the cloud overnight without keeping a laptop connected.

3 mention(s) 3 session(s) First in DEM305 @ 00:10:38 1 external link(s)
Also called: `copilot --cloud` GitHub sandboxes, Cloud Sandboxing for GitHub Copilot in public preview

About

Boyle demonstrates `copilot --cloud` in the Copilot CLI, which stands up what is called a GitHub sandbox—micro VMs provisioned in a matter of seconds that are completely stateful. They suspend after 10 minutes of inactivity by the agent, and resuming the session from the local CLI spins the micro VM back up with all state intact. He shows the full lifecycle by putting it on autopilot to add an emoji to his README, then notes the changes don't appear locally, illustrating how he can offload long-running implementation work to a sandbox, close his laptop, and return to a finished prototype.

    Why your AI code doesn’t ship: Closing the gap to production
    Mario Rodriguez, Evan Boyle

    Copilot `--cloud` lets users delegate tasks to run in the cloud so they can close their laptop and go home without keeping it connected to the internet. It is built on top of GitHub sandboxes, fast micro-VMs that spin up in a matter of seconds. The sandboxes are stateful and isolated, with tightly scoped credentials, so users can safely test out PRs separate from their laptop environment or kick off a task to run all night, ready to return to in the morning. The demo also showed switching into an autopilot 'Yolo' mode to run tasks in the cloud.

    GitHub Copilot Anywhere: From Remote Control CLIs to Cloud Sandboxes
    Ellie Bennett, Denizhan Yigitbas

    Cloud sandboxing for GitHub Copilot, now in public preview, gives every Copilot session that uses it its own isolated environment in the cloud, sandboxed down to the tools, file system, and network you choose to grant it. Because the session lives in the cloud, the host machine no longer needs to be running—you can connect even if your laptop disconnects from the internet or shuts down. It also lets users run many heavy agents in parallel by allocating cloud resources instead of overloading local resources.
