Staged/incremental rollouts with freeze capability

Replaces the previous all-at-once deployment, letting the team freeze a build after catching a problem at 8% rollout

1 mention(s) 1 session(s) First in BRK204 @ 00:38:56 0 external link(s)

About

The team now does staged, incremental rollouts of VS Code through their update server, replacing the previous approach of deploying to 100% all at once. This lets them observe effects in the wild across their 40+ million users, which differs greatly from internal Insiders usage, and the same data drives both the live dashboard and the update server. The capability to freeze a build and fall back to previous builds is built into their build site; in the example shown a build was frozen after reaching 8% rollout because a problem was caught, letting them stop it before it affected most users. This incremental rollout and freeze tooling is relatively new and has grown substantially as the team's needs expanded.
