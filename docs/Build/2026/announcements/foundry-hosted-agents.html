Hermes Agent on Nemotron 3 Super completes a real email-to-pull-request task and retains a learned skill across separate sessions and services

About

This demo shows a Foundry hosted agent deployment running Hermes Agent powered by Nemotron 3 Super, with Nemotron Super and Nano models running on Foundry managed compute endpoints. The agent is granted access to external data—GitHub, Teams, and email—through Entra ID [inferred]. In the scenario, the presenter delegates a real feature-request task from a colleague's email about adding chat completions endpoint support to an internal benchmarking repo (LLM Perf Bench); because the hosted agent is connected to Outlook and GitHub through Foundry, it finds the relevant email, makes the code changes, and opens a pull request autonomously without the email being pasted into context.

    Unlock Claude in Microsoft Foundry
    Keiji Kanazawa, Caroline Matthews

    Foundry hosted agents are agents you build with custom code in any framework you want — including the GitHub Copilot SDK, LangChain, LangGraph, or the Claude Agent SDK — and run within Microsoft Foundry inside a hosted container sandbox. You start by building and testing the agent on your local machine, then move the application up into the cloud sandbox hosted in Foundry Agent Service. The sandbox is automatically secured and set up with the authentication needed to access Foundry resources, such as calling Claude models in Microsoft Foundry. It also facilitates the authentication needed to securely connect to tools and MCPs that host your enterprise data.
