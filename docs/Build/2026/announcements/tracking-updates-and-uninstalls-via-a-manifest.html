Tracking, updates, and uninstalls via a manifest

`dotnetup list` tracks installed components and the channels being followed; `dotnetup update` installs new releases and removes out-of-date installs no longer needed.

1 mention(s) 1 session(s) First in OD804 @ 00:30:38 0 external link(s)

About

`dotnetup list` tracks what is currently installed along with the explicit runtime requests being followed, and supports the component name @version pattern (e.g. `dotnetup runtime install aspnetcore@8.0`). When new versions of runtimes release, a simple `dotnetup update` installs them and brings out-of-date installs up to the requested state. This works because dotnetup keeps a manifest — an installation tracker in a data directory in the user directory — acting like a lock file for the declared/desired state of the system, while global.json remains the way to describe development requirements across repos and developers.
