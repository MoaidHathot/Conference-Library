End-to-end identity propagation via Entra ID and OAuth 2

A user's Azure Entra ID identity is propagated into the Oracle database itself through an OBO token flow, so the database applies its own security rules to the agent's queries as if the user connected directly.

About

After an agent is registered as an MCP client, an OAuth 2 workflow handles authentication: the user logs in, their Azure Entra ID credentials are verified, and they grant the agent permission to act on their behalf via an OBO (on-behalf-of) token, after which the agent obtains an access token without repeated logins. The user's Entra ID identity is then propagated into the Oracle database itself, so the database sees the user as themselves rather than the agent. This allows Oracle's own security rules to be applied to the agent's queries as if the user connected directly, provided the user's group membership grants access to the relevant resources.
