Concept

"Safe outputs" security model

The agent receives only read access to the repository; a separate post-run workflow step holds the permissions to create issues or pull requests, segregating responsibilities.

1 mention(s) 1 session(s) First in DEM350 @ 00:08:32 0 external link(s)

About

For agentic workflows to be secure, the agent is not given any permissions besides read access to the repository. Instead, a mechanism called "safe output" runs after the agent completes, and that workflow step holds the access to perform actions such as creating an issue or a pull request, segregating those responsibilities from the agent. This ensures the agent cannot hallucinate, delete the code base, or remove files, keeping the developer in control of what gets merged or discarded.
