Official description

Developers are building interactive, AI‑driven analytics workflows, but the data layer often can’t keep up. Dashboards stall, pipelines miss SLAs, and agentic analytics break when queries are slow. In this session, learn about how a new engine in Fabric Data Warehouse delivers a faster, more predictable foundation accelerating reporting, pipelines, and agentic experiences without re‑architecting your stack.

Summary

Overview

Microsoft Fabric Data Warehouse is introduced as a serverless, lakehouse-based analytics engine being retooled for AI-driven and agentic workloads. The session centers on a new GPU-accelerated query engine ("Query Acceleration") plus a broad slate of developer experience, T-SQL, SQL analytics endpoint, enterprise readiness, and billing enhancements that aim to deliver faster, more predictable performance without re-architecting existing stacks.

Key announcements

  • GPU-accelerated data warehouse / Query Acceleration (limited preview) [00:03:59m05sm10sp05sp10s] — A new engine executes queries or query portions directly on GPUs, requiring no query rewrites and applying to every SQL endpoint and warehouse in a workspace once enabled.
  • ALTER COLUMN in place [00:10:57m05sm10sp05sp10s] — Data type changes no longer require rebuilding tables.
  • ALTER TABLE inside a transaction [00:11:16m05sm10sp05sp10s] — Multiple schema changes can be grouped as a single unit with automatic rollback on failure.
  • New T-SQL functions [00:11:59m05sm10sp05sp10s] — Fuzzy string matching (Levenshtein, Jaro-Winkler), new concatenation operations, UNISTR, DATE_BUCKET, and the ANY_VALUE aggregate.
  • Enhanced scalar UDFs [00:12:25m05sm10sp05sp10s] — Procedural constructs including loops, multipath execution, and if/then/else branches.
  • Lakehouse table health checks [00:12:50m05sm10sp05sp10s] — A diagnostic stored procedure (sp_get_table_health_metrics [inferred]) pinpoints root causes like fragmentation, small files, excessive deletes, or delayed checkpoints.
  • Configurable retention [00:15:03m05sm10sp05sp10s] — Default 30-day retention is now adjustable from 1 to 120 days for time travel, point-in-time restore, and table clones.
  • Distributed bitmap filters (coming soon) [00:15:21m05sm10sp05sp10s] — Compact filters from smaller tables are pushed down to large fact-table scans to eliminate non-matching rows early.
  • Inline Copilot in the SQL editor [00:17:46m05sm10sp05sp10s] — AI assistance embedded directly in the query flow for joins, optimization, and natural-language-to-SQL.
  • Metadata sync (public preview) [00:20:31m05sm10sp05sp10s] — Re-architected sync makes lakehouse data queryable in seconds rather than minutes.
  • Time travel on SQL analytics endpoint [00:22:12m05sm10sp05sp10s] — Query data as it appeared at any prior point, governed by the lakehouse retention period.
  • CI/CD for SQL analytics endpoint plus pre/post-deployment scripts (coming soon) [00:23:02m05sm10sp05sp10s] — Git-based version control via DacFX projects, Fabric pipeline integration, and scripted prep/cleanup steps.
  • Migration assistant GA [00:25:04m05sm10sp05sp10s] — Live connectivity GA (no DACPAC extraction) and .SQL file input (public preview) supporting Azure Synapse, SQL Server, and any T-SQL source.
  • Custom SQL pools [00:26:43m05sm10sp05sp10s] — Adjustable allocation of the default 50/50 split between select and non-select workloads.
  • Node-based billing model [00:27:39m05sm10sp05sp10s] — Per-compute billing with a one-minute minimum then per-second granularity.
  • Cache cooldown [00:28:43m05sm10sp05sp10s] — Configurable window to keep compute warm and avoid cold starts.

  • Enterprise readiness: object explorer scaling, CI/CD, migration, workload management, and billing
