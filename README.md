# Conference Library

A community-maintained reference of conference sessions, generated as a self-contained static HTML wiki. Each session page includes:

- Full transcript (cleaned, speaker-attributed where available)
- A long-form AI summary (announcements, key points, demos, references — generated by GitHub Copilot)
- Five evenly-spaced frames sampled from the on-demand video
- The original conference's own description and any provided AI summary as a fallback
- Speakers, level, type, topics, tags, and direct links back to the canonical session page
- All references from the session links

The whole site is static HTML + one vanilla-JS file + Lunr.js for client-side search — no build step, no server, no JavaScript framework. The rendered site lives under `docs/<Conference>/<EventId>/` and is served straight from GitHub Pages.

## Conferences

The repo is structured to host multiple conferences side by side:

| Conference | Status |
|---|---|
| Microsoft Build | implemented (`-Conference Build`) — uses the public `api-v2.build.microsoft.com` catalog API and Medius on-demand video |
| Others | adapter pattern not yet implemented; structure is in place so future conferences can sit alongside Build with no template/CSS changes |

## Attribution & content reuse

Per-conference session metadata, transcripts, captions, frames, and descriptions are sourced from the public catalog APIs of each conference. **All rights to the underlying session content remain with the original owners (Microsoft and the respective speakers for Microsoft Build).** This repository exists purely as a community-friendly index that makes those public catalogs easier to search and reference; every per-session page links back to the canonical source.

The AI summaries are generated by GitHub Copilot from the official transcripts; they are best-effort and may contain inaccuracies — the linked transcripts and the original sessions remain the source of truth.

## Repository layout

```
Conference-Library/
  catalog/
    <Conference>/                 # e.g. Build
      <EventId>/                  # e.g. 2026
        catalog.json              # full session metadata from the API (~3 MB for Build 2026)
        sessions-index.json       # diff-friendly slim index
        ingestion-report.json     # written by Invoke-BuildIngestion.ps1
        summaries-report.json     # written by Get-SessionSummaries.ps1
  sessions/
    <Conference>/
      <EventId>/
        <SESSION-CODE>/           # e.g. KEY01, BRK101
          rich-manifest.json      # per-session manifest produced by ingestion
          transcript.md           # cleaned transcript (Markdown, timestamped)
          transcript.vtt          # raw WebVTT pulled from the source video service
          transcript-official.docx  # official transcript document, if provided
          summary.md              # Copilot-generated summary (8-section format)
          ai-description.html     # source's own AI summary (HTML), if any
          frames/
            frame-001-<HH-MM-SS>.jpg
            ...                   # five JPEGs, evenly spaced (interior only)
  templates/
    site/
      layout.html
      index.body.html
      session.body.html
      assets/
        style.css
        app.js
        lunr.min.js               # vendored, 28.8 KB
  scripts/
    Get-BuildCatalog.ps1          # 1. crawl the Microsoft Build session catalog API
    Invoke-BuildIngestion.ps1     # 2. download captions, sample frames, write manifests
    Get-SessionSummary.cs         # 3a. (single-session) Copilot summarizer, .NET 10 file-based
    Get-SessionSummaries.ps1      # 3b. drive the .cs summarizer across all sessions, in parallel
    Build-Book.ps1                # 4. render the static docs/ HTML site
  docs/                           # GitHub Pages deploy root (tracked in git)
    index.html                    # multi-conference landing (auto-generated)
    <Conference>/
      index.html                  # per-conference year list (auto-generated)
      <EventId>/                  # per-event site (auto-generated)
        index.html
        sessions/<CODE>.html
        assets/
        frames/<CODE>/*.jpg
        catalog.json
        search-index.json
```

## Workflow

All four steps are idempotent. Re-running only does work for new or updated content.

```powershell
# 1. Pull the full Microsoft Build 2026 session catalog (~24 s for 443 sessions).
pwsh scripts/Get-BuildCatalog.ps1 -Conference Build -EventId 2026

# 2. For each session in the catalog: fetch captions + sample frames + write manifest.
#    Default concurrency 10. Re-runs skip sessions whose catalog fetchedAt hasn't moved.
pwsh scripts/Invoke-BuildIngestion.ps1 -Conference Build -EventId 2026

# 3. Generate a long-form summary per session via GitHub Copilot.
#    Default concurrency 10. Re-runs skip sessions whose summary.md is newer than transcript.md.
pwsh scripts/Get-SessionSummaries.ps1 -Conference Build -EventId 2026

# 4. Render the static HTML site into docs/Build/2026/ (and refresh the two landing pages).
pwsh scripts/Build-Book.ps1 -Conference Build -EventId 2026

# Preview locally (any static file server works):
python -m http.server 8080 -d docs
# then open http://localhost:8080/
```

To rebuild just one session for development:

```powershell
pwsh scripts/Invoke-BuildIngestion.ps1 -Conference Build -EventId 2026 -OnlyCodes KEY01 -Force
pwsh scripts/Get-SessionSummaries.ps1 -Conference Build -EventId 2026 -OnlyCodes KEY01 -Force
pwsh scripts/Build-Book.ps1 -Conference Build -EventId 2026
```

`-Conference` defaults to `Build` for backward convenience; you can drop it while only Microsoft Build is wired up.

## Requirements

- **PowerShell 7.4+** (`pwsh`) — for all `.ps1` scripts.
- **.NET 10 SDK** — for `scripts/Get-SessionSummary.cs` (file-based program). First run does a NuGet restore (~10–15 min for the Copilot SDK); subsequent runs are < 1 s.
- **GitHub Copilot** signed in for the current user — the summarizer authenticates via the locally signed-in Copilot session (`UseLoggedInUser=true`). Any tier that exposes a `claude-opus-*` model works.
- **ffmpeg** on `PATH` (or under `%LOCALAPPDATA%\Zakira.Replay\portable\ffmpeg.exe`) — for frame sampling. Range-streamed; no full video downloads.
- **node** on `PATH` (optional but recommended) — used by `Build-Book.ps1` to pre-build the Lunr search index. Without node, the site falls back to a substring-match index.

No build step, no npm install, no webpack. The site is plain HTML + one CSS file + two JS files (`app.js` + vendored `lunr.min.js`).

## Customizing the look

The CSS uses CSS custom properties on `:root`. Re-theming is a one-block edit at the top of `templates/site/assets/style.css`:

```css
:root {
    --c-bg:        #fafafa;
    --c-text:      #1a1a1d;
    --c-accent:    #0066d8;
    /* ... */
}
```

Re-run `scripts/Build-Book.ps1` to copy the updated assets into `docs/<Conference>/<EventId>/assets/`.

## Adding a new event year (same conference)

1. Add `-EventId 2027` (or whichever) to the four-step workflow above.
2. The site is built per-event under `docs/Build/2027/`; `docs/Build/index.html` automatically grows a new card linking the new year. The catalog and sessions live in sibling per-year folders, nothing else changes.

## Adding a new conference

The directory layout already accommodates this; the missing piece is a catalog crawler for the new conference. Once that exists:

1. Run `pwsh scripts/Get-<NewConf>Catalog.ps1 -Conference <NewConf> -EventId <year>` to populate `catalog/<NewConf>/<year>/catalog.json` in the same shape as the Build catalog.
2. Run `Invoke-BuildIngestion.ps1 -Conference <NewConf> -EventId <year>` (the ingestion driver is conference-agnostic provided the catalog records have `sessionCode`, `onDemand`, `downloadVideoLink`, `durationInMinutes`, etc.).
3. Run `Get-SessionSummaries.ps1` and `Build-Book.ps1` with the same parameters.
4. `docs/index.html` will pick up the new conference automatically on the next render.

## Hosting on GitHub Pages

This repo is set up to deploy via Pages's "deploy from a branch" mode:

1. After committing and pushing, go to **Settings -> Pages**.
2. Source: **Deploy from a branch**.
3. Branch: **main**, Folder: **/docs**.
4. Save. The site lands at `https://<owner>.github.io/<repo>/` within ~1 minute.

The root `docs/index.html` is the multi-conference landing; each `docs/<Conference>/` is a per-conference year list; each `docs/<Conference>/<EventId>/` is a self-contained per-event site.
